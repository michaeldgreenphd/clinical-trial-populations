## display_rule, which is the whole rendering contract

`display_rule` is a property of a **row**, that is of a (geo_code, estimand, metric) triple. It is not a property of a geography. The same country can be `show` for `pw_raw` and `withheld` for `std_gcomp`, and that is the normal case rather than an edge case.

| display_rule | ui_meaning |
|---|---|
| show | render normally, include in any ranking |
| badge_concentration | render, and show the concentration badge with the driving trial from g1_unit_drivers.csv; still rankable |
| omit_from_ranking | render only when the user asks for this geography by name; never include in a ranking or a top-N list |
| withheld | no value exists for this estimand; render the gate_reason text instead of a number, and do not substitute another estimand |

## The support floor, in one paragraph

A geography needs `support_share >= 0.25` to receive a standardized value (`std_gcomp`, `std_modal`). Below it the value is **withheld**: the cell is empty and `gate_reason` says why. This governs WHICH ESTIMAND is available, never whether the geography exists. All 34 gate-passing countries and all 39 gate-passing units carry descriptive values (`pw_raw`, `tw_median`); 13 and 12 respectively carry adjusted ones.

## Sentinels

Two conventions are in use and the difference matters, so it is stated rather than glossed.

**Columns with an explicit sentinel.** `estimand` uses `not_applicable` where a metric has no estimand. The flag columns `concentration_flag`, `below_support_floor` and `crosses_parity` use `true` / `false` / `not_applicable`. These never contain a blank, because a blank cannot distinguish 'false' from 'does not apply' and that distinction is the three-state rule.

**Columns where a blank IS the marker.** A blank in a VALUE column means the quantity does not exist for that row, and `display_rule` plus `gate_reason` say which of the two reasons applies (withheld below the support floor, or the metric does not apply to this estimand). ## The geography-tab views

Rendered from `b1_view_definitions.csv`, which is the SAME file `geo_reader.R` reads and the adjusted figures filter by. Nothing below is restated by hand. `include_withheld = FALSE` on the adjusted views is the B2 decision: a panel plotting `std_gcomp` cannot plot a geography that has none, so those rows are excluded by definition of the view rather than carried and hidden. The withheld row is still in the long table with its reason for any caller that wants to ask.

| view_name | geo_level | estimands | include_withheld | n_geographies | rationale |
|---|---|---|---|---|---|
| country_descriptive | country | pw_raw/tw_median | TRUE | 34 | Every gate-passing country. Descriptive estimands need no covariate support, so no geography is withheld and nothing is excluded from the ranking. |
| country_adjusted | country | std_gcomp | FALSE | 13 | Only countries with an adjusted value. Withheld rows are excluded BY DEFINITION of the view: a panel that plots std_gcomp cannot plot a geography that has none. |
| state_descriptive | us_state | pw_raw/tw_median | TRUE | 39 | Every gate-passing US unit, on the same terms as the country descriptive view. |
| state_adjusted | us_state | std_gcomp | FALSE | 12 | Only units with an adjusted value, on the same terms as the country adjusted view. |

source("geo_reader.R")
views <- geo_tab_views("<run directory>")   # every view in b1_view_definitions.csv
geo_view("<run directory>", "country_adjusted")
rankable(views$country_descriptive)   # drops withheld and omit_from_ranking rows
